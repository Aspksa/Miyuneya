# Многоуровневая долговременная память Miyuneya

## Что изменилось

После слияния когнитивной памяти №45 активная память получила долговременный SQLite-архив.
Раньше ограничение `600` фактов/правил, `400` эпизодов и `1500` связей могло удалять
давние записи из JSON. Теперь эти цифры определяют **размер горячего набора**, а не
общий объём сохранённых знаний.

- **Горячая память:** `data/memory.json`. Здесь находятся наиболее значимые
  факты, правила, недавние и ещё не обработанные эпизоды, активные связи.
  Закреплённые пользователем факты сохраняются в ней даже сверх мягкого лимита.
- **Холодная память:** `data/memory-archive.sqlite`. SQLite хранит полные
  JSON-объекты фактов, эпизодов и связей, включая старые идентификаторы,
  ссылки на источники и даты. FTS5 индексирует текст для локального поиска.
  Архив не использует Cloud.ru и не создаёт дополнительных запросов к модели.
- **Когнитивная память:** производные связи по существующим фактам и источникам.
  Не заменяет исторический архив и не объявляет гипотезы достоверными фактами.

Когда активная память переполняется, приложение **сначала** коммитит полный
снимок этих трёх видов записей в SQLite с `WAL` и `synchronous=FULL`, а
**затем** атомарно записывает сокращённый `memory.json`. Сбой между двумя
операциями может оставить дубликат в SQLite, но не удаляет исходную запись.
При первом запуске старый переполненный `memory.json` сначала архивируется,
а уже затем сокращается. Записи, потерянные предыдущими версиями до этого
обновления, восстановить из ничего невозможно: используйте старые резервные копии.

## Использование

В разделе **Память → Знания → Когнитивная** отображается количество архивных
фактов/правил, эпизодов и связей. Для поиска старых записей используйте
«Найти в архиве». Доступно также:

```text
GET /api/memory/archive?q=тема&limit=20
```

Без параметра `q` возвращаются только счётчики. При обычном вопросе
подходящие **подтверждённые и неистёкшие** архивные факты и эпизоды локально
добавляются в ограниченный контекст ответа (до 1400 символов).
Архивная запись не становится подтверждённой от того, что была сохранена.
Повторное чтение архива не вызывает дополнительных обращений к Cloud.ru.

Команда «забудь ...», явное удаление записи и сброс памяти должны также
исключать совпадающие архивные данные. Сброс удаляет всю SQLite-историю
архивной памяти. Приватный режим не сохраняет новые разговоры; выключение
памяти блокирует использование архивных данных в контексте ответов.

## Резервное копирование

Копируйте **всю папку `data` при полностью остановленной Miyuneya**.
Одна экспортированная копия `memory.json` уже не содержит всей истории:
добавьте к архивной копии `memory-archive.sqlite` и, при некорректном
завершении, связанные с ней файлы `-wal` / `-shm`. Не удаляйте
WAL-файлы работающей базы. Лучше восстанавливать согласованный снимок
всей папки `data`, не смешивая поколения.

При повреждении архива приложение должно остановиться с ошибкой,
не затирая исходные данные пустым архивом. При недостатке свободного места
запись в архиве должна завершиться ошибкой **до** удаления горячих записей.
Если база восстановлена из старой копии, часть более новых данных может
потребовать отдельного восстановления из журналов или резервных копий.

## Технические границы

- Содержимое архива не зашифровано; защита физического диска остаётся
  отдельной задачей.
- Архивируются факты/правила, эпизоды и графовые связи. Лимиты журналов,
  напоминаний, мыслей и других коллекций пока остаются прежними.
- Индекс FTS5 — лексический, не самостоятельный векторный индекс всех
  архивных документов. Векторы для активной памяти остаются в
  `data/memory-vectors.json`.
- Периодическая очистка старых записей **отключена**: удаление выполняется
  только по пользовательскому действию. Долгосрочное накопление требует
  контроля свободного места и независимого резервирования.
- Реальная надёжность на переносном M.2 SSD должна проверяться отдельно:
  успешный CI не моделирует физическое отсоединение работающего диска.
