# Автономный когнитивный процесс Hayumeri

## Архитектура

При запуске памяти Miyuneya запускается **не отдельная языковая модель**, а менеджер
фонового анализа `server/cognitive-daemon.ts`. По необходимости он запускает
изолированный дочерний процесс Node.js `scripts/cognitive-worker.mjs`. Рабочий
чат, SQLite и API Cloud.ru продолжают работать независимо от вычислений ребёнка.

- Передача через IPC ограничена **последними 600 фактами и 1500 связями**.
  Процесс не получает API-ключ, документы с диска, историю чата или путь к базе,
  не выполняет облачных запросов и не модифицирует оригинальную память.
- Все изменения сохраняются через существующее атомарное сохранение
  `data/memory.json` с последующей постановкой задачи на анализ.
- Локальная очередь не хранит исходные сообщения или снимки. Она хранит
  SHA-256 последнего обработанного/ожидающего снимка и результат анализа в
  `data/cognitive-daemon.json`. После повторного запуска незавершённая задача
  строится заново из текущей памяти.
- Задания объединяются (debounce), одновременно выполняется только одно.
  На анализ выделено до 15 секунд. Ошибки не уничтожают знания и повторяются
  с ограниченной задержкой; процесс автоматически запускается снова при новой
  задаче. Результат не может перезаписать выводы для более новой версии памяти.
- При выключении памяти или включении приватного режима процесс
  останавливается, производный анализ очищается, ожидающее задание аннулируется.
  При восстановлении режима выполняется анализ текущего состояния.
- При выходе приложения фоновый дочерний процесс закрывается и
  ожидающий отпечаток остаётся в очереди для последующего восстановления.

## Автоматическое развитие и границы доверия

Фоновая обработка извлекает кандидатов отношений между уже сохранёнными
фактами, выявляет возможные числовые противоречия и расхождения отрицаний.
Все эти выводы имеют статус **«кандидат»**, не создают новых фактов и
не подтверждают истинность данных самостоятельно.

Дополнительно вычисляется ограниченная оценка recall@3 на уже
сохранённых явных связях: сравнивается поиск по словам и сочетание
поиска со связями графа. Вторую стратегию разрешено использовать
только при улучшении на имеющемся небольшом тестовом наборе;
иначе остаётся прежняя лексическая стратегия. Это **прокси-метрика**
восстановления известных связей, не независимое доказательство
улучшения точности ответов. Даже при выборе графовой стратегии
в ответ попадают только действующие подтверждённые связи из памяти.

Прогресс виден в существующем разделе
**Мозги Hayumeri → Знания → Когнитивная**:
статус процесса, количество циклов, проверенных записей, найденных
кандидатов и возможных противоречий. Никаких новых обязательных
настроек Cloud.ru или вкладок не требуется.

## Производительность и восстановление

- Поиск кандидатов ограничен последними 240 фактами и 48 выводами.
- Контрольные запросы ограничены 24 примерами; результат ограничен 150 КБ.
- Очередь обрабатывает только актуальную версию, поэтому серия записей
  не запускает отдельный процесс на каждый факт.
- Ошибка анализа не мешает чтению и сохранению рабочей памяти.
- `data/cognitive-daemon.json` является производной диагностикой:
  его можно восстановить пересчётом, но пользовательский архив SQLite
  и `data/memory.json` восстановить без резервной копии нельзя.

## Что ещё не реализовано

Ни локальный worker, ни proxy-оценка не обучают веса LLM и не
переписывают произвольно исходный код. Изменение стратегии основано
на небольшом наборе уже сохранённых связей. Полноценная проверка
качества ответов по независимым задачам, глубокие семантические
связи с архивом и сложная проверка подлинности первоисточников —
отдельные будущие этапы.
