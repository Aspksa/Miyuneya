# Автономный выбор изучения и контроль качества (пакет №51)

## Приоритеты фонового изучения

Локальный модуль `server/cognitive-learning.ts` сохраняет устойчивую
очередь задач исследования в `data/cognitive-learning.sqlite`.

Приоритеты основаны на типе пробела (это **не вероятность истины**):
- **90** — важное утверждение без проверяемого первоисточника.
- **85** — возможное противоречие с существующими записями.
- **65** — утверждения, которые необходимо сопоставить во времени.
- **25** — возможная тематическая связь, требующая подтверждения.

Задания имеют ID, тип, приоритет, отпечатки и ID исходных записей.
Дубликаты объединяются; если источник изменён, истёк или потерял
актуальность, старое исследование закрывается или скрывается.
Блокируются чувствительные категории и признаки секретов.
Приведённые цифры обозначают порядок обслуживания, а не уверенность.

При очередном **фоновом локальном** обходе архива Miyuneya сначала
отбирает подходящие ранее сохранённые записи для первой задачи,
а затем читает обычную страницу архива. Всё происходит в Node.js
и SQLite без дополнительных вызовов Cloud.ru.

Это означает выбор предмета для дальнейшей проверки,
**не автономный доступ в Интернет** и не установление истины.
Если в имеющейся памяти нет источника, задача остаётся открытой;
модель не сочиняет отсутствующие доказательства.

## Что значит оценка качества ответов

В работающем чате уже существует необязательная проверка утверждений
по явным цитатам. Теперь после каждого успешно доставленного ответа
сохраняются только его отпечаток и статус:
- `supported`: ответ прошёл имеющуюся формальную проверку источников.
- `blocked`: проверка отклонила утверждения.
- `uncertain`: источник не позволил сделать вывод.
- `unverified`: такой проверки для ответа не было.

Отдельно считаются подтверждённые сигналы **отмены созданной
помощницей записи**. Они показывают неудовлетворённость конкретным
действием, но не автоматически означают фактическую ошибку ответа.

Последние 50 ответов используются для статистики; два окна
по 25 ответов позволяют увидеть изменение доли пройденных проверок.
Окно оценивается только при пяти и более ответах, реально
прошедших процедуру проверки. Это **прокси-метрика покрытия
источниками, а НЕ независимая оценка точности**. При недостатке
данных статистика показывает «не определено», а не выдуманный
процент улучшения.

Статистика не заставляет автоматически менять модель, переписывать
факты или принимать собственные выводы за доказательства.

## Управление и безопасность

Все измерения и текущая пятёрка задач видны в существующем
разделе **«Когнитивная»**, отдельный интерфейс не требуется.

SQL-база хранит до 500 последних статусов проверки и до 200 сигналов
отмены; **тексты вопросов и ответов туда не копируются**.
Приватный режим, отключение памяти и полный сброс очищают производный
журнал и задачи. Сохранять этот файл при переносе/резервировании следует
только вместе с остальной папкой `data`.

Ограничения: мониторинг охватывает лишь реально проверенные ответы
и сохранённые отмены, не все ошибки пользователя или языковой модели.
Для оценки истинной точности нужен отдельный независимый размеченный
набор вопросов с надёжным эталоном и проверяемыми источниками.
