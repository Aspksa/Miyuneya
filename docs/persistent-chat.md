# Долговременное хранение переписки Miyuneya

## Новая архитектура (SQLite, пакет №38)

Начиная с этого обновления действующим хранилищем переписки является **встроенный SQLite** (`node:sqlite`, Node.js 22.18+) с WAL и `synchronous=FULL`. Установка дополнительных баз данных, Python, прав администратора или npm-зависимостей не требуется.

| Путь | Назначение |
| --- | --- |
| `data/chats/archive.sqlite` | Сообщения, диалоги, связи, метаданные и полнотекстовый индекс FTS5 |
| `data/chats/archive.sqlite-wal` и `-shm` | Служебные файлы SQLite во время работы: **не удалять и не копировать отдельно от работающей базы** |
| `data/chats/attachments/*.blob` | Отдельные оригиналы пользовательских файлов, проверяемые по SHA-256 |
| `data/chat-backups/<дата>/archive.sqlite` | Ежедневный согласованный онлайн-снимок с помощью SQLite Backup API |
| `data/chat-backups/<дата>/attachments` | Неизменяемые вложения, сохранённые вместе со снимком базы |
| `data/chat-backups/<дата>/manifest.json` | SHA-256 базы и каждого вложения; контрольный манифест |
| `data/chats/manifest.json`, `data/chats/conversations/`, `data/chats/index.json` | **Старый JSON-архив**, не удаляется после миграции |
| `data/assistant.json` | Личные настройки и API-ключ Cloud.ru; не входят в архив чата |

**Миграция:** перед первым использованием SQLite старый файловый JSON переносится транзакционно. Если перенос прерван, SQLite отменяет незавершённую транзакцию. Оригиналы JSON остаются нетронутыми. Нельзя вручную удалять старые файлы до независимой проверки новой базы и восстановления из резервной копии.

## Сохранение, связи и ветвления

Сообщение пользователя сохраняется до запроса к Cloud.ru. Длинный потоковый ответ имеет версии промежуточных сохранений. Каждое сообщение получает уникальный идентификатор; старая версия не может перезаписать новую, а конфликтующие ID отклоняются. Информацию о том, на какое сообщение дан ответ, хранит `parent_message_id`.

У любого отображаемого сообщения есть «Ответвить». Новая ветка ссылается на оригинальный диалог и наследует его историю **без копирования сотен или тысяч исходных сообщений**. В старом разговоре сообщения не изменяются. Ветки также доступны после перезапуска.

FTS5 индексирует сохранённые сообщения на диске. Кнопка «Восстановить поиск» и автоматическая глубокая проверка позволяют перестроить индекс из исходного текста. Индексы по диалогам, времени и связям ускоряют навигацию. Прокрутка длинной переписки загружает только необходимые страницы.

## Резервное копирование

Через 12 секунд после запуска приложение проверяет, не пора ли сделать проверку целостности и ежедневную копию. После этого повторяет проверку по расписанию каждые 30 минут, но само резервирование выполняется **не чаще одного раза в 24 часа**, если предыдущая копия была успешной. Фоновая операция уступает время другим задачам на медленных дисках. Если Miyuneya закрыта весь день, задача выполняется после следующего запуска, а не в выключенном приложении.

Используется SQLite Online Backup API; после завершения копия и все вложения проверяются с помощью SHA-256. Неудачная или неполная копия не объявляется успешной. Существующие резервные копии не перезаписываются. Проверка доступна также вручную в существующих настройках чата.

**Важно:** автоматическая копия находится **на том же носителе проекта**, если папка `data` не перенесена. Она защищает от некоторых ошибок программы, но не от поломки или потери самого SSD. Для защиты на годы периодически копируйте папку `data/chat-backups` на **другой физический диск** или защищённое хранилище. На Windows не копируйте только открытый `archive.sqlite` без WAL: останавливайте Miyuneya или используйте созданный онлайн-снимок.

## Мониторинг и предупреждения

Внутри **существующих настроек чата** показываются число разговоров, сообщений, вложений, их объём, размер SQLite и дата последнего успешного резервирования. Доступны кнопки «Проверить целостность», «Создать копию сейчас», «Восстановить поиск». Измеряется длительность операций записи/чтения (без сохранения текстов и API-ключей в журнале метрик). Появляются предупреждения об отсутствии свежей копии, проблемах с индексом, нехватке диска и медленной записи.

Повреждённые файлы вложений не выдаются как корректные. Если SQLite обнаруживает нарушение целостности, новые записи блокируются — до восстановления или ручной проверки, чтобы не уничтожать информацию.

## Экспорт, импорт и ограничения

Потоковый экспорт JSONL по-прежнему доступен из чата и подтверждается завершающей записью SHA-256. Импорт JSONL предварительно сверяет контрольную сумму; затем выполняет изменения одной транзакцией. Импорт старого JSON дополняет данные, но не удаляет существующие разговоры. Во время импорта используется временный файл, чтобы не помещать многогигабайтный архив в память.

Для защиты от злоупотреблений и исчерпания ресурсов установлены лимиты: отдельное сообщение до 10 млн символов, вложение до 15 МБ, старый JSON-импорт до 32 МБ, JSONL-импорт до 8 ГБ. **Общего лимита количества сообщений или диалогов нет.** При очень больших объёмах данные переносятся через каталог SQLite и проверяемые снимки.

Вложения пока сохраняются как файлы текущего разговора; они не отправляются автоматически в Cloud.ru и не становятся частью контекста ИИ. Это намеренное разделение хранения переписки и передачи содержимого сторонней модели.

Личные данные и файлы хранятся локально, без шифрования самим модулем. Не публикуйте папку `data` в GitHub. Полное уничтожение данных, отказ носителя и вредоносные программы не предотвращаются одной SQLite — требуются независимые резервные копии.
